# QQ 群招募与发布方案（让别人愿意、且方便地做用户评价）

> 配合 `user_test/tasks.md`（任务脚本）、`user_test/record_sheet.md`（记录表）、`user_test/raw.csv`（录入）、
> `user_test/host_guide.md`（主试手册）使用。本文件只解决一件事：**在 QQ 群里怎么发、发什么、怎么收数据。**
>
> **⚠️ 链接会变**：Cloudflare 临时隧道的地址每次重启都不同。
> 发文前先执行 `python deploy\show_public_url.py` 取**当前**地址，再把下面文案里的
> `【粘贴当前链接】` 换成它；不要直接抄本文档里的示例地址。
>
> **本文件的作业口径**（来自作业第 5 条要求）：邀请**至少 3 名**同学完成**指定操作**，记录
> **① 任务完成率 ② 操作时间 ③ 对结果的理解情况**；再结合反馈提出**至少 3 条改进建议**，并**区分是模型问题还是界面问题**。
> 下面所有话术都是按这个口径设计的：同学回的那 4 件小事，正好一一对应 `raw.csv` 的字段
> （对照表见第 7.4 节），不需要再补第二遍问题。
>
> **实际执行情况（2026-10-08 补记）**：本轮最终没有走"群发链接 + 群内口头回答"这条路，而是改用了
> **问卷星在线问卷**（9 题：4 简答 + 5 级单选），因此**上面话术里对应的 T2/T3 两类判定没有采集到**。
> 问卷原文、题目到 `raw.csv` 字段的对照、以及与设计版 T1–T5 的差异表都记在
> **`user_test/questionnaire.md`**；结论与"哪些通过线无法判定"见 `user_test/summary.md`。
> 下次再找人测试时，**优先用本文件的面对面方案**（能主试计时、能现场追问 T2/T3）。

## 0. 发之前先做 4 件事（10 分钟）

| # | 事项 | 怎么做 |
|---|---|---|
| 1 | 先问群主 / 班长能不能发 | 一句话私聊："老师要求我做一次用户评价（至少 3 位同学），能在群里发一条求助吗？只发一条，不刷屏" |
| 2 | 自己先用**手机流量**试一次链接 | 关掉 WiFi 用流量打开，确认能进；记下首次加载大约多少秒（写进文案，免得别人以为坏了） |
| 3 | 确认隧道与健康检查正常 | `python deploy\show_public_url.py` → 本机与公网都应打印 `OK (HTTP 200)`；同时把电脑上 `share_web.cmd` 的窗口留着别关 |
| 4 | 定好"收几个人"和编号规则 | 作业**最低 3 人**，建议**争取 5 人**（`tasks.md` 第 4 节的通过线是按 5 人写的，3 人的换算见该节备注）；参与者只记 `P1…P3+`，**不写姓名**；先到先得，够了就在群里说"满了，谢谢大家" |

> 如果要做**面对面**（最推荐，能测用时），把电脑带上、`record_sheet.md` 打印 5 页（只找到 3 个人也能交）。

## 1. 怎么发（发送顺序比文案更重要）

1. **先发"试探版"**（第 2 节，1–2 行）→ 有 1–2 个人回应后，再发正文；
2. **正文二选一**：想省事、想一次把话问全 → 发**第 3 节的一条完整版**；想阅读率更高 → 发**第 4 节的标准版**（分 4 条短消息依次发，QQ 群里长文容易被刷过去）；
3. **链接单独占一条消息**（QQ 才会把它变成可点链接/卡片），且**不要**把链接夹在长段文字中间；
4. 发送时间选 **19:00–22:00**（群里活跃），避开上课时间；
5. 需要 `@全体成员` 的话**必须先征得群主同意**；
6. 全程措辞是"**帮我评价界面**"，不是"帮我做作业"，也不是"求求了"。

## 3. 一条完整版（**群里只发一条时用这个**；作业口径：至少 3 人）

> 把 `【粘贴当前链接】` 换成当前地址、`还差 X 位` 换成真实数字即可发。它把作业要求的四样东西
> （完成率 / 操作时间 / 对结果的理解 / 改进建议）都问在一处，同学**只回一次消息**就够了；
> 语气是**故意口语化**的（短句、少括号、"想到啥说啥"），同学更愿意照着做、也更容易说实话。

```
【求帮忙🙏 5 分钟，帮我看看这个睡觉小工具】

作业要求我找至少 3 个同学帮我测一下，还差 X 个，能帮我一下吗？

链接（手机点开就能用，不用注册、不用装 App、也不用写名字）：
【粘贴当前链接】
第一次打开要等个十几秒，是隧道慢，不是坏了。真打不开就在群里说一声，我马上换地址。

就三步：
① 填一下今天的活动量（步数、中高强度活动分钟、久坐分钟）
② 点「生成预测」，看看它说今晚大概能睡多久
③ 再往下翻，看「为什么会这样？」那一页

然后回我 4 个问题，想到啥说啥，不用打得很正式：
1. 三步都点到了吗？有没有哪一步卡住、或者不知道点哪？
2. 从点开链接到看到结论，大概花了几秒？（估一个数就行，这个我作业里要写）
3. 这个数你会当作"大概就这样"，还是"肯定就是这样"？
4. 你觉得它为啥给这个数？如果只能改一处，你会改哪？
   是界面没说清，还是模型本身算得不对？

再帮我打 5 个分（1=很不同意，5=很同意），一行发我就行：
能看懂结果 / 觉得估得挺准 / 影响因素合理 / 没有让我焦虑的措辞 / 我愿意用它

两句实话：这个原型用的是别人的历史数据，你填的只是今天的活动，所以数准不准真不用在意，
觉得不准就直接说不准，我心里有数。我主要想看界面有没有把话说清楚。
我也不会存你输入的内容，记录里只有"同学1、同学2"这种编号。

不用写长，想到啥说啥最有帮助。谢啦！🙏
```

> 说明：上面三步里的第 ② 步"点「生成预测」"是按钮的实际文字、第 ③ 步"「为什么会这样？」"是解释页的实际标题
> （`app/app.py` 第 130、240 行），这样远程同学不会因为找不到入口而假失败；
> **但不要把"区间/可信度是什么意思"讲给他们听**——那是 T2 要测的东西。
>
> ⚠️ 提醒框（**只有一行，不影响你发出去的字**）：第 5 项里的 B「觉得估得挺准」测的是**主观准确度**，
> 不是原设计的"信任校准"，所以它**不参与通过线判定**（示例数据下必然偏低，别当成界面差）；
> 信任校准用第 3 问 / 问卷第 8 题判定。想让 B 回到原口径：把这句换成「我知道它只是个估计、不一定准」。

**第 ① 条：说清请求与门槛**

```

**第 ② 条：链接单独发（换行隔开，方便点击）**

```
【粘贴当前链接】

**第 ③ 条：要做的事 + 必须如实说明的部分**

```
进去以后就是三步：填今天的活动 → 看它说今晚大概能睡多久 → 看「为什么会这样？」那一页。

两件实话先说清：
1) 这个原型用的是"示例用户的历史数据"，你填的只是"今天的活动"，

2) 界面不会保存任何输入（没有数据库、没有埋点），我只要匿名结论，不用告诉我姓名。

请边点边说感受：哪一步看不懂、哪个数字让你怀疑、哪里让你觉得别扭或被评判。
```

**第 ④ 条：反馈方式（给 3 个选项，选最省事的）**

```
反馈方式随便挑一个（都很短）：

A. 打字（最常用，1 分钟）：照抄填空回我就行
   1) 三步都点到了吗：① ② ③ 都做到 / 卡在第__步（不知道点哪就说哪一步）
   2) 大概花了：__秒（从点开链接到看到结论；估个大概就行）

   4) 它为啥给这个数：____；最想改的一处：____（界面没说清 / 模型算得不对）
   5) 打分 A B C D E = __ __ __ __ __
      A 能看懂结果 / B 觉得估得挺准 / C 影响因素合理 / D 没有让我焦虑的措辞 / E 我愿意用它
   这 5 条正好是我作业要记的东西（完成率 / 耗时 / 你对结果的理解 / 改进建议），

B. 当面：如果你在【教学楼/宿舍楼】，我拿电脑过去，你当场用，5 分钟完事

C. 语音：嫌打字麻烦，直接发 30 秒语音，把上面 5 条念一遍也完全可以

不用全做，能给我 A 就足够了，谢谢！🙌
```

## 7. 只用 QQ 群怎么收数据（见不到面的自助版）

### 7.1 最省事：让同学**直接按模板回一条消息**

把这段模板发给对方（不用建任何问卷）：

```
方便的话照这个格式回我就行（照抄填空，1 分钟）：
1) 三步都点到了吗：① ② ③ 都做到 / 卡在第__步（不知道点哪就说哪一步）
2) 大概花了：__秒（从点开链接到看到结论；估个大概就行）
3) 这个数你会当"大概就这样"还是"肯定就是这样"：大概 / 肯定
4) 它为啥给这个数：____；最想改的一处：____（界面没说清 / 模型算得不对）
5) 打分 A B C D E = __ __ __ __ __
   A 能看懂结果 / B 觉得估得挺准 / C 影响因素合理 / D 没有让我焦虑的措辞 / E 我愿意用它
（不想打字就发 30 秒语音，把上面 5 条念一遍也完全可以）
```

> 这 5 条就是按 `raw.csv` 的字段设的：第 1、2 条 → 完成率与操作时间，第 3 条 → T2/T3 的
> "理解情况"，第 4 条 → 改进建议素材与归因；逐字段对照见第 7.4 节。
> ⚠️ 第 5 条里的 B 项口径变化见第 3 节的提醒框（它测的是主观准确度，不参与通过线判定）。

### 7.2 想更"正式"：腾讯问卷 / 问卷星（2 分钟建好）

题目（照抄即可）：

1. 能看懂结果（1–5）
2. 觉得估得挺准（1–5）⚠️ 口语版口径＝主观准确度，**不作为通过线证据**，见第 3 节提醒框
3. 影响因素合理（1–5）
4. 没有让我焦虑的措辞（1–5）
5. 我愿意用它（1–5）
6. 三步都点到了吗？哪一步卡住、或不知道点哪？（开放题 → 完成率）
7. 大概花了多少秒？（填空，**自报、只能当参考**；作业要记"操作时间"，所以放在前面）
8. 这个数你会当作"大概就这样"还是"肯定就是这样"？（开放题 → 理解情况 T2 / 信任校准）
9. 你觉得它为什么给这个数？影响最大的是什么？（开放题 → 理解情况 T3）
10. 如果只能改一处，你会改什么？更像界面没说清，还是模型算得不对？（开放题 + 归因 → 改进建议）

问卷标题与开头就写："课程作业原型可用性测试（匿名、5 分钟、非医疗用途）"。

### 7.3 必须承认的取舍（写进 `summary.md`）

| 字段 | 方式 A/B（当面 / 局域网） | 方式 C（远程自助） |
|---|---|---|
| T1 完成情况 | ✅ 观察得到 | ✅ 可自报 |
| T1 用时、提示次数 | ✅ 可精确记录 | ❌ 写"未采集" |
| T2 是否把预测当事实 | ✅ 可追问 | ⚠️ 只能从开放题推断，标注"推断" |
| T3 是否真的打开了解释页 | ✅ 可观察 | ❌ 写"未采集" |
| T4 可行动的改变（`tasks.md` 里标为"可选"） | ✅ 可追问 | ⚠️ 问卷未问 → 写"未采集（T4 可选）"；想补就在回执里追问一句 |
| T5 五个评分 + 两个开放题 | ✅ | ✅ |

> 结论写法：**方式 A/B 的样本用于判定通过线，方式 C 只用于补充主观评分与文案线索**，
> 并在表格里把两条渠道分开统计（`user_test/tasks.md` 第 4 节的通过线不把 C 混进来算）。

### 7.4 作业要求 ↔ 群里怎么问 ↔ 落到哪个字段（对照表）

> 这张表是给老师看的"证据链"：作业第 5 条要的四样东西，每一项都能指出**从哪句话收上来、写进哪一列**。

| 作业要求记录的东西 | 群里/私聊怎么问（本文件） | 落到 `raw.csv` 的字段 | 远程自助（方式 C）拿得到吗 |
|---|---|---|---|
| **任务完成率** | 回执第 1 条"三步都完成了吗、卡在第几步" | `t1_completed`（+ `t1_hints` 若对方提到提示） | ✅ 自报 |
| **操作时间** | 回执第 2 条"大概多少秒" | `t1_seconds` | ⚠️ 只能自报估算，录入时在 `notes` 写"用时自报" |
| **对结果的理解情况** | 回执第 3 条"这个数你会当'大概就这样'还是'肯定就是这样'"+ 回执第 4 条"它为啥给这个数" | `t2_mentions_range` / `t2_mentions_uncertain` / `t2_treats_as_fact` / `t3_top_factor` / `t3_direction_correct` / `hardest_step` | ⚠️ 可自报理解，但 `t3_found_explain`（是否真点开了解释页）**未采集**，写"未采集" |
| **≥3 条改进建议 + 区分模型/界面** | 回执第 4 条"它为啥给这个数 / 最想改的一处" + 问卷第 10 题的归因追问 | `hardest_step` / `one_change` / `notes` → 汇总进 `summary.md` 第 4 节的"归因"列 | ✅ |
| 主观评价（辅助） | 回执第 5 条 / 问卷第 1–5 题打分 | `q1_understand … q5_willing`（其中 **B 项＝主观准确度**，不参与通过线，见第 3 节提醒框） | ✅（推荐用，别省） |

> 所以：**群里发的那一条消息已经问全了**；面对面时额外只有两样东西是远程拿不到的——
> 精确用时、以及"是否真的点开了解释页"（这也正是 `host_guide.md` 里最推荐当面做的原因）。

## 8. 发布纪律（8 条，避免好心办坏事）

1. **只发一轮**（一条试探 + 一条正文），别连着刷屏；有人回应后再补细节；
2. 不 `@全体成员`（除非群主同意）；也不要给每个人单独私发群链接；
3. **链接单独一条消息**发，方便点；并把"打不开就回我"写在链接那条里；
4. 不许承诺任何健康/准确率效果（"它能预测你睡多久"这种话不要说，只能说"这是统计估计"）；
5. 群里**不收集姓名、手机号、学号**，参与者只用 `P1…P3+` 编号；
6. 只发本班/本群这样熟悉的小群，**不要把无鉴权链接转到陌生大群**（谁拿到都能打开）；
7. 有人拒绝就别追问，"好的，谢谢"就过去——自愿参与，不打扰；

## 9. 有人说"打不开"怎么办（按顺序 3 步 + 话术）

1. **看电脑**：`share_web.cmd` 那个窗口还在跑吗？窗口一关，链接立刻失效；
2. **重开隧道**：双击 `deploy\share_web.cmd` 得到**新**地址（旧地址作废），
   或先用 `python deploy\show_public_url.py` 看健康检查是不是 200；
3. **换局域网**：让同学连同一个 WiFi，用 `python -m scripts.run_app` 打印的 `http://192.168.x.x:8501`；
   还不行就走"当面版"（第 5、6 节）。

**回复话术（照抄）**

```
刚重启了一下，麻烦再点一次：【新链接】
（第一次要等十几秒；如果还是打不开，我 1 分钟内换局域网地址给你，或者我拿电脑过去找你）
```

**QQ / 微信内置浏览器的小坑**：可能弹"即将离开 QQ / 继续访问"——点继续即可；
加载特别慢时可让对方在右上角选择"**用系统浏览器打开**"。
