# 主试手册：把原型交给参与者，并记录他们的数据

> 配合 `user_test/tasks.md`（任务脚本）、`user_test/record_sheet.md`（可打印记录表）、
> `user_test/raw.csv`（最终录入）使用。本手册只解决一件事：怎么跑起来、怎么让别人用、数据记到哪。
> 要在 QQ 群 / 微信里招募并分发（含远程自助问卷题目），用 `user_test/qq_invite.md` 里的现成文案。
> 前提：本项目已训练好模型（`models/model.pkl` 等，实测 `created_at = 2026-10-04T01:45:22`），
> 本机 `Python 3.13.5` + `streamlit 1.45.1` 已就绪。

---

## 0. 先选一种"给用户"的方式

- A. 同机面对面（推荐）：适用场景＝教室、宿舍，一次一人；优点＝能完整观察 T1 用时、提示次数、卡在哪一步，最贴合 `tasks.md`；代价 / 限制＝需要你的电脑在场；一人一次约 5–8 分钟
- B. 局域网（参与者用自己手机）：适用场景＝参与者想用自己的设备；优点＝更接近真实使用，可多人同时填；代价 / 限制＝需同一个 WiFi + 放行防火墙；屏幕小，用时观察略难
- C. 远程自助（部署 + 问卷）：适用场景＝见不到面；优点＝不受距离限制；代价 / 限制＝拿不到 T1 用时/提示次数、T3 是否真的找到解释页；需要额外部署

> 结论：尽量用 A 或 B，C 只作为补充样本，并在 `summary.md` 里注明哪些字段缺失（不要编造）。

## 1. 本机运行（当前项目状态：一条命令即可）

```cmd
:: 推荐：会先检查依赖与模型产物，再打印本机/局域网地址，然后启动界面
python -m scripts.run_app

:: 等价写法（不带检查与地址提示）
streamlit run app/app.py
```

Windows 下也可以直接双击项目根目录的 `run_app.cmd`（内容就是 `cd` 到项目根目录 + 调用上面的脚本，纯 ASCII 以免 cmd 编码问题）。

从零复现全流程（换电脑 / 助教验收时用）：

```cmd
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m src.features      :: 清洗 + 特征 + 划分（读 data/raw/fitbit/…）
python -m src.train         :: 多模型对比 + 验证集选优 + 分位数模型
python -m src.evaluate      :: 测试集评价 + 出图 + 错误分析（界面不依赖它）
python -m scripts.run_app
```

改过代码后自检（不启动界面也能验证链路）：

```cmd
python -m scripts.smoke_test     :: 特征 → 预测 → 解释
python -m scripts.test_app       :: 三个页面能否渲染
```

## 2. 让参与者用手机 / 另一台电脑访问（方式 B）

1. 启动：`python -m scripts.run_app`，记下打印的 局域网访问：`http://192.168.x.x:8501`（本机实测为 `192.168.10.160`，换了网络会变）；
2. 首次运行 Windows 弹出防火墙提示 → 勾选专用网络并允许（否则手机连不上）；
3. 参与者手机连同一个 WiFi，浏览器输入上面的地址即可看到同一个界面；
4. 打不开时按顺序排查：① 手机是否用了流量而不是 WiFi；② 防火墙是否放行；③ 用 `ipconfig` 核对 IPv4 地址；④ 换端口 `python -m scripts.run_app --port 8600`；
5. 想更安全（只给自己用）：`python -m scripts.run_app --local-only`；
6. 测试结束按 Ctrl+C 停止——这个地址只在服务运行期间有效，不是长期服务，测完就关。

## 3. 把项目复制到另一台电脑（"把项目给用户"的字面含义）

必须带：

- `src/`、`config/`、`app/`、`scripts/`：原因＝代码本体
- `requirements.txt`、`run_app.cmd`、`README.md`：原因＝让对方知道怎么装、怎么跑
- `models/` 里的 `model.pkl`、`model_card.json`、`history_sample.csv`（建议连 `quantiles.pkl`、`feature_importance.csv` 一起）：原因＝缺了界面直接报"尚未训练模型"；`history_sample.csv` 是界面默认载入的演示历史

作业交付还要带：`docs/`、`reports/`（含 `figures/`）、`user_test/`。

不必带：`.venv/`、`__pycache__/`（虚拟环境与缓存）。`data/raw/` 约 150 KB（主链路必需的 3 个 CSV），随包提供，重跑清洗/训练时需要它。

> 交付包里的 `data/raw/` 只保留主链路必需的 3 个 CSV（约 150 KB）：`data/raw/fitbit/` 下的
> `dailyActivity_merged.csv` + `sleepDay_merged.csv`，以及 `data/raw/sleep_health/` 的第二数据集。
> 没随包提供的是分钟级文件与另一段导出（合计数百 MB，只服务于 `scripts/build_fitbit_2seg.py` 那个实验分支）；
> 要重跑那个分支时，按 `docs/03_data_source.md` 的下载来源把两个导出目录放回 `data/raw/fitbit/` 即可。
> 界面（`run_app.cmd`）、自检（`smoke_test`、`test_app`、`feature_check`）与对照实验（`gate_experiment`）都不需要这些文件，实测全部通过。

> ⚠️ 最容易踩的坑：`.gitignore` 里排除了 `models/*` 和 `data/raw/*`，两条都会咬人。
> 用 git / GitHub / Streamlit Cloud 分发时：
> ① 模型不会自动进仓库 → 对方打开界面报 `ModelNotTrainedError`（"尚未训练模型"）；
> ② 原始数据不会自动进仓库 → 对方重跑 `python -m src.features` 时报找不到 CSV。
> 两种解法：
> ```cmd
> :: (a) 强制把模型产物与 3 个原始 CSV 纳入版本库（体积小，可直接入库）
> git add -f models/model.pkl models/quantiles.pkl models/model_card.json models/history_sample.csv models/feature_importance.csv data/raw/sleep_health data/raw/fitbit
>
> :: (b) 不带模型/数据，让对方拿到 data/raw/fitbit/... 两个 CSV 后自己训一遍
> python -m src.features && python -m src.train
> ```
> 最省事的分发方式：右键项目文件夹 → 发送到 → 压缩(zipped)文件夹，对方解压后 `pip install -r requirements.txt` 再 `run_app.cmd` 即可。

## 4. 参与者在界面里"填数据"填的是什么

界面是输入 → 结果 → 解释三步（侧边栏可以"重新开始"）：

- 会问：今天走了多少步、中高强度活动分钟、久坐分钟；可选心率 / BMI / 年龄（不知道就保持 0）；
- 不会问："你打算几点上床睡觉"——当前数据集（Fitbit 日表）没有该字段，界面刻意不显示这个假控件。若参与者问"怎么没有填睡觉时间的地方"，如实回答"这个工具现在不用这一项"，并把这个提问记进 `notes`（`tasks.md` T1 已把这列为有价值发现）；
- 参与者的输入不会被保存到文件（项目没有数据库、没有埋点），可以如实告知，降低隐私顾虑。

> ⚠️ 已知界面缺陷（测前必读；测试期间不要改 `app.py`）：「可选：补充信息」里的心率 / BMI / 年龄
> 在当前数据集里不参与任何计算。主试自查实测（2026-10-04）：把它们从 心率 1 / BMI 0.5 / 年龄 1
> 一路改到 心率 150 / BMI 35 / 年龄 60，预测值一字不变（恒为 533.9 分钟，区间 [374, 587]），
> 因为 `models/model_card.json` 的 70 个特征里没有 `heart_rate_mean` / `bmi` / `age`。
> 界面同时没有做值域校验（心率 1 bpm、BMI 0.5 这类不可能值也被照收）。处理原则：
> 1. 测试期间不要改代码——改了会让"修复前 / 修复后"两批样本不可比；修复放到测完再做；
> 2. 参与者问到时如实回答："这一版没用上这三项，你留 0 就行，这个我记下来。"
>    （不透露任务答案，因此不算引导，可写进记录）；
> 3. 该发现已写成 `summary.md` 第 4 节的候选 8、9、10，并区分了归因（假控件与缺校验＝界面/文案；
>    树模型不能外推＝模型/数据）。

> ⚠️ 测试时必须如实说明的已知限制：原型载入的历史是 演示用户 `2026352035` 的 28 天记录（2016-04-12 ~ 2016-05-12），
> 参与者填的只是"今天的活动"，会拼在这段历史之后参与计算（见 `src/predict.py::feature_row_from_inputs`）。
> 所以本轮测试检验的是界面能不能把结果和不确定性说清楚，不是"对参与者本人预测得准不准"。
> 建议话术（不透露任务答案，因此不算引导）：
>
> > "这个原型现在用的是示例用户的历史记录，你填的是今天的活动；所以请你重点看它说的东西对不对得上你的理解，先不用管数字准不准。"
>
> ⚠️ 参与者（也包括你自己）几乎一定会说的一句话：「怎么填都是 8 小时，感觉很不准」——必读：
> 这不是操作错误，也不是界面坏了，而是上面那条限制的必然结果。主试自查实测（2026-10-04，236 次预测，走 `src/predict.py::predict_one` 同一条路径）：
>
> - 界面载入的演示历史：数值＝用户 `2026352035` 的 28 天，其平均睡眠 506.2 分钟 = 8 小时 26 分（σ 42.3，范围 357–573）
> - 界面默认输入（7000 步 / 25 / 600）：数值＝预测 488.8 分钟 = 8 小时 09 分
> - 步数 0 → 40000：数值＝537 → 481 分钟（极差 56.9；≥15000 步后恒为 481，树模型不外推）
> - 中高强度活动 0 → 180 分钟：数值＝488 → 488 分钟（极差仅 6.3，用户根本感觉不到）
> - 久坐 0 → 900 分钟：数值＝484 → 419 分钟（极差 69.5）
> - 随机 200 组输入（步数 0–40000、中高强度 0–180、久坐 0–900）：数值＝预测全部落在 402–543 分钟（6 小时 42 分 ~ 9 小时 03 分），其中 45% 会显示成"8 小时 xx 分"、78.5% 落在 7.5–9 小时

>
> 处理原则：照实逐字记录原话（这是 `summary.md` 候选 10、13 的证据），
> 不要主动解释成因（解释了就测不到参与者自己的理解），也不要在测试中途改代码或文案；
> 若参与者追问"那这个 8 小时到底是谁的"，按第 125 行的口径如实回答"是示例用户的"。
>
> ⚠️ 配套的文案缺陷（已定位，测后修）：结果页写的是"和你最近记录的平均值（8 小时 26 分）相比"（`app/app.py` 第 185 行）、
> 解释页写的是"把这一项换成你的历史平均水平"（第 243 行）、`src/explain.py` 第 53 / 161 行把演示用户的统计量标成"你的长期平均"——
> 这三处用的其实都是演示用户的历史，却写成了参与者自己的，与第 120–125 行"如实说明"的口径自相矛盾，
> 也正是"数字不是我、却被读成在说我"这个误解的直接来源（见 `user_test/summary.md` 候选 13）。

## 5. 记录者侧的数据：怎么把 5 份记录变成 `raw.csv` 与 `summary.md`

1. 打印 `user_test/record_sheet.md`（每位参与者一页足够）；
2. 照 `user_test/tasks.md` 逐任务提问，原话尽量逐字记（原文比评分有价值）；
3. 当天把纸上的内容录进 `user_test/raw.csv`：
   - `是/否` 统一写成中文，不要写 `☐`；
   - 原话里含逗号时用英文双引号包住（Excel 另存为 CSV 会自动处理）；
   - `participant` 只写 `P1`…`P3+`（至少 3 人，最多备 5 个编号），不要写真实姓名；
4. 用 `user_test/summary.md` 汇总：
   - 第 1 节按通过线填实测值（T1 完成率、T1 用时中位数、T2/T3 关键判断、Q1 均分、Q4 风险项）；
   - 第 2 节放逐字原话（≥3 条）；
   - 第 4 节逐条写改进建议：先写实际做了什么（依据是主试实测还是参与者原话，要标明是哪一种），再写还没做的与不做的原因，每条标注"界面/文案 vs 模型/数据"、优先级、预估工作量；
   - 第 5 节由人写结论（这一节不要交给脚本生成）。
5. 时间安排建议：一次连做 3 人（约 20 分钟）→ 休息 → 再做 2 人，避免主试疲劳导致记录变粗；每人 5–8 分钟。

> 数据完整性红线：`summary.md` 里每个数字都要能在 `raw.csv` 找到来源；
> 缺失的字段（尤其是方式 C 拿不到的 T1 用时、提示次数）要写明"未采集"，不要补一个看起来合理的值。

## 6. 远程自助（方式 C）如何落地

> 交付包不含上线脚本，下面是远程自助（方式 C）实际的做法与取舍。
> 本轮实际使用的是**在线问卷**（问卷星，题目原文见 `questionnaire.md`）＋ 把界面地址发给参与者
> （访问范围取决于你怎么发布界面：局域网见第 2 节；想让参与者用手机流量也能打开，
> 按下面第一条把项目部署到 Streamlit Community Cloud，入口文件填 `app/app.py`）。

- 界面：把项目推到 GitHub 后在 Streamlit Community Cloud 建应用（入口文件填 `app/app.py`）；
  记得先按第 3 节把 `models/` 强制入库，否则云上会报"尚未训练模型"。得到 `https://xxx.streamlit.app` 后发给参与者；
- 记录：用腾讯问卷 / Google Form 镜像记录表的后半部分——T5 的 5 个评分、两个开放问题（最费劲的一步、最想改的一处），
  可选再加"T1 是否完成""大致用时（自己估）"；题目原文与发送话术直接抄 `user_test/qq_invite.md` 第 7 节；
- 必须承认的取舍：远程无法观察 T1 用时与提示次数、无法确认 T3 是否真的打开了"为什么是这个结果"页面 → 这几个字段在
  `summary.md` 中标注"远程自助未采集"，并把方式 C 的样本与 A/B 分开统计；
- 公网地址无鉴权：谁拿到网址谁就能用，只在测试期间开着；界面不保存任何输入，可如实告知参与者；
- 结论写法建议：方式 A/B 的样本用于判定通过线，方式 C 只用于补充主观评分与文案线索。

## 7. 常见问题速查

- 界面报 `尚未训练模型` / `ModelNotTrainedError`：原因＝`models/` 缺 `model.pkl` 或 `model_card.json`；处理＝跑 `python -m src.features && python -m src.train`，或按第 3 节强制入库模型文件
- 启动就报端口占用：原因＝8501 已被其他程序占用；处理＝`python -m scripts.run_app --port 8600`
- 手机打不开局域网地址：原因＝不同网段 / 防火墙拦截 / 用了流量；处理＝连同一 WiFi、放行专用网络、`ipconfig` 核对 IP
- 启动后浏览器没自动打开：原因＝无头环境 / 默认浏览器未注册；处理＝手动访问打印出的 `http://localhost:8501`
- 报告图里中文变方框：原因＝缺中文字体（多见于 Linux/容器）；处理＝Windows 已设 `Microsoft YaHei`；其他平台装中文字体后重跑 `python -m src.evaluate`
- 控制台输出中文乱码：原因＝输出被重定向到文件，编码仍是 GBK；处理＝用 `set PYTHONIOENCODING=utf-8` 再运行（`setup_console()` 已处理日志场景）
- `pip install` 卡住/超时：原因＝网络受限；处理＝`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`
- 想清空重跑：原因＝需要干净的中间产物；处理＝删 `data/processed/*` 与 `models/*`（都可重新生成），再跑 features → train → evaluate
- 参与者说"这个数字准吗"：原因＝正常提问，不是操作错误；处理＝如实回答"这是统计估计，不构成医疗建议"，并把提问记进 `notes`
- 参与者问"心率 / BMI 填了有用吗"（甚至填了 1 bpm、BMI 0.5）：原因＝这三个框在当前数据集里不参与计算，且界面没有值域校验；处理＝如实回答"这一版没用上，留 0 就行"，并记为界面/文案缺陷（`summary.md` 候选 8、9）；不要在测试中途改代码
- 参与者说"怎么填都是 8 小时 / 感觉很不准"，或发现"步数填多少结果都差不多"：原因＝预测几乎由演示用户的历史基线决定（该用户均值 506.2 分钟 = 8 小时 26 分；步数 0→40000 只动 56.9 分钟、中高强度 0→180 只动 6.3 分钟、久坐 0→900 动 69.5 分钟），且树模型不外推（≥15000 步后恒为 481 分钟）；随机 200 组输入里 45% 显示为"8 小时 xx 分"；处理＝照实逐字记录原话（候选 10、13 的证据）；不要主动解释成因——解释了就测不到他的真实理解；成因与话术见第 4 节的两个 ⚠️ 框
