## 2. 与设计版任务脚本的差异（**必须如实说明**）

| 设计版（`tasks.md`） | 远程自助版（本问卷） | 后果 |
|---|---|---|
| T1 主试计时 | 第 2 题**自报**秒数 | 用时只能算"自报中位数"（实测 10 秒）；P3 答"100ms"判为无效 |
| **T1 另需记录提示次数 / 操作错误 / 卡在哪一步** | 第 1 题只问"有没有 bug 或卡壳" | `t1_hints` 全部**未采集**；P2 报出的 bug 是这道题唯一捞到的信息 |
| **T2 复述不确定性**（"能不能当成一定会发生的事"） | **没有对应题目** | `t2_mentions_range / t2_mentions_uncertain / t2_treats_as_fact` 全部**未采集** → 通过线无法判定 |
| **T3 指出主要影响因素**（"哪一项影响最大、变长还是变短"） | **没有对应题目** | `t3_*` 四个字段全部**未采集** → 通过线无法判定 |
| **T4 可行动的改变** | **没有对应题目** | `t4_action` 未采集 |
| T5 第 4 项"界面上没有让我焦虑或被评判的措辞" | **没有对应题目** | `q4_no_anxiety` **未采集**（这是 4.2 第 15 条要补的题） |
| 记录年龄 / 性别 / 手环使用 | **没有对应题目** | `age_group` / `gender` / `device_user` 全部**未采集** |
| 追问"哪一步最费劲""只改一个地方" | 合并成第 4 题一个开放题 | `hardest_step` 未采集；`one_change` 拿到的多是"无""挺好的" |

> **为什么不补造**：缺失的字段一律写「未采集」。按 `docs/05_prompt_log.md` §3.2 的反向清单，
> "帮我编一点数据 / 补一个合理值"属于**刻意不问**的那一类：编出来的满意度和"没测"在报告里
> 看起来一样漂亮，但一旦被追问原始答卷就站不住。
