# 04 AI 辅助使用声明

> 本文档如实说明：**哪些部分用了 AI、用在什么环节、AI 出了什么错、我是怎么验证的**。
> 原则：AI 用于加速"把决策写成代码"和"查 API 用法"，
> **不用于**决定研究问题、判断数据是否合法、编造数据与结论。
> 配套文档：**`docs/05_prompt_log.md`（提示词记录）**——本文档说的是"AI 用在哪"，那份说的是"我怎么问的"。

---

## 1. 使用的 AI 工具与角色

| 工具 | 用途 | 使用范围 |
|---|---|---|
| Cline（VS Code 中的编码 Agent，底层为大型语言模型） | 生成/修改代码、运行命令、定位报错、起草文档 | 项目脚手架与实现、调试、文档草稿 |
| 通用对话式大模型（用于查 API 用法、解释报错） | 查询 scikit-learn / pandas / streamlit 的接口与常见坑 | 临时查询，不产生交付代码 |

AI 参与程度：**高**（代码实现层面）。但下面这些由**人**决定，AI 不得代替：

1. 研究问题与预测时点的定义（"就寝前预测当晚睡眠时长"）；
2. 数据集的合法性与许可判断、泄漏字段的黑名单；
3. 验收标准的数值（MAE ≤ 0.75 小时、提升 ≥ 15%、覆盖率 70%–90%）；
4. 界面信息架构、文案口径、免责声明的措辞；
5. 错误分析中"为什么错"的解释；
6. 用户测试的组织与结论。

## 2. 具体分工明细

| 环节 | AI 参与 | 人的参与 | 验证方式 |
|---|---|---|---|
| 需求分析（`docs/01`） | 整理成表、补齐风险清单 | 确定用户/场景/成功标准/边界 | 逐条对照作业要求 |
| 数据集甄别（`docs/03`） | 汇总候选与对比维度 | **决定选哪个、判断许可与伦理** | 打开数据集页面核对字段与许可 |
| 数据清洗（`src/data_io.py`） | 生成清洗函数与报告 | 定义合法范围（如 `bedtime` 0–1440）、判定哪些列必须丢弃 | 看清洗报告的剔除量是否合理；对越界样本人工抽查 |
| 特征工程（`src/features.py`） | 生成周期编码、滞后、滚动、个人基线代码 | **指定"只能用就寝前信息"这一约束** | 泄漏自检报告 + 手工核对 `shift(1)` |
| 模型与训练（`src/train.py`） | 生成候选模型与调参循环 | 选择候选模型族、确定以验证集选优 | 跑通并对比 val/test 指标是否一致 |
| 评价与可视化（`src/evaluate.py`） | 生成指标与 7 张图 | 设定验收阈值、判断图是否可读 | 人工看每张图；中文字体是否方框 |
| 解释与文案（`src/explain.py`、`app/app.py`） | 起草中文文案模板 | **审措辞：是否夸大因果、是否像医疗建议** | 逐句通读；用户测试中检验可理解性 |
| 调试 | **主要由 AI 定位** | 判断修复方案是否合理 | 修复后重跑全流程 + 自检脚本 |
| 文档与报告 | 起草结构与文字 | 补充结论、错误原因、改进建议 | 核对所有数字与运行输出一致 |
| 用户测试（`user_test/`） | 生成任务脚本与记录表模板 | **组织测试、记录、写改进建议** | 原始记录可追溯 |

## 3. AI 生成的代码在实际运行中暴露的问题（重要）

这部分是"AI 使用说明"里最有价值的内容：**AI 写的代码不能直接信，必须跑。**

| # | 问题 | 现象 | 定位方式 | 修复 |

| 1 | Ridge 调参网格键名写成 `alphas`（复数） | `TypeError: Ridge.__init__() got an unexpected keyword argument 'alphas'`，训练直接中断 | 阅读 traceback，发现网格参数被当作 kwargs 透传 | 网格键名改为与 sklearn 参数一致的 `alpha`（见 `config/dataset.py`） |

## 4. 我如何验证 AI 的产出（三层验证）

| 层级 | 命令 | 检查什么 |
|---|---|---|
| 静态 | `python -m compileall -q src scripts config` | 语法/缩进/引号问题（中文字符串最容易出错） |
| 链路自检 | `python -m scripts.smoke_test` | 预测范围合理、区间包住点预测、**方向性**正确（提前睡 → 预测更长；数据集没有该字段时改测"填了不改变结果"）、解释文案非空且不含 `None` |
| 系统验收 | `python -m src.evaluate` | MAE / 相对基线提升 / 区间覆盖率三项自动判定，并生成图表供人工查看 |
| 界面自检 | `python -m scripts.test_app` | **两条人群线**的三个页面在无浏览器环境下渲染无异常（Streamlit 官方 `AppTest`）；并断言「含性别的数据集必须出现性别控件、手环线必须没有、改性别后预测必须变化」 |
| 特征自检 | `python -m scripts.feature_check` | 新特征"只加不减、只看过去、不跨用户、值域合法"，并确认线上数据集**没有**开启新特征（8 项断言，退出码 0/1） |
| 人工复核 | 肉眼 + 用户测试 | 图表中文是否可读、文案是否夸大因果、数字是否与报告一致 |

除此之外还有三条"不靠工具"的原则：

1. **数字必须能溯源**：报告里的每个指标都必须能在 `reports/*.json`、`*.csv` 或运行日志里找到；
2. **不编造结论**：没有真实数据就不写真实结论，只写"合成数据用于验证链路"；
3. **不把 AI 的自信当证据**：AI 说"这样最准"不算依据，必须由本次运行的结果说话。

## 5. 哪些内容**没有**使用 AI

- 所有验收标准的具体数值与理由；
- 数据来源的选择、许可判断与伦理声明；
- 预测时点的定义与泄漏字段黑名单；
- 错误分析中的原因解释（如"周五误差最大可能与社交作息有关"这类判断由人给出，AI 只负责把已有结论整理成文）；
- 用户测试的执行、记录与改进建议（**招募文案由 AI 起草、由我改词并发送**，见 `user_test/qq_invite.md`）；
- 最终报告的结论与局限性陈述。
