> 本文档说明：**用什么跑、为什么这样选、缺依赖会怎样、怎么验证**。
> 所有版本号均为目标机器（Windows + Anaconda）上的实测值，不是"建议值"。

## 1. 运行环境

| 项目 | 实测值 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11（cmd） | 开发与验证环境 |
| Python | 3.13.5（Anaconda 发行版） | 选 3.13 是因为 scikit-learn / pandas / streamlit 均已提供正式版轮子 |
| 交互方式 | `python -m <模块>` | 避免 `__init__.py` 路径问题，任何目录下都能运行 |
| 控制台编码 | 启动时切换为 UTF-8 | Windows 控制台默认 GBK，打印中文标点/emoji 会直接抛 `UnicodeEncodeError` 中断流程（这是本项目实际踩到的坑，见 `src/config.py::setup_console`） |

### 1.1 为什么不使用深度学习

1. **数据规模**：公开数据只有几百到几千条日级记录，神经网络在这个量级上没有优势，
   反而更难调、更难解释、更容易过拟合；
2. **可解释性要求**：作业要求给用户"解释反馈"，树模型 + 置换重要性 + 反事实归因的组合
   更容易翻译成人话；
3. **可复现性**：CPU 上 30 秒内跑完全流程，评委/助教可现场复现；
4. **风险**：PyTorch 轮子体积大、版本敏感，会给"一键复现"带来不必要的失败点。

结论：**GBDT / Ridge 级别的模型 + 严谨的评价**比"上一个大模型"更符合本任务。

## 3. 系统架构与数据流

### 3.1 模块职责

| 模块 | 职责 | 关键约定 |
|---|---|---|
| `config/dataset.py` | 唯一配置源：数据集路径、列名映射、单位换算、切分方式、模型网格、验收标准 | 换数据集只改这里 |
| `src/config.py` | 配置访问层 + 路径常量 + 规范列名 + 控制台编码设置；`output_dirs()` 按数据集给出输出目录（线上数据集=扁平 `models/`、`reports/`；标了 `output_scope="dataset"` 的写各自子目录） | 业务代码不硬编码路径 |
| `src/data_io.py` | 读取原始文件 → 列名映射 → 清洗（范围校验/去重/缺失统计） | 输出 `data/processed/*_clean.csv` 与清洗报告；排序按"数据集实际存在的列"（支持无日期列的横截面数据集） |
| `src/features.py` | 日历、周期编码（sin/cos）、滞后、滚动、个人基线、**类别列 one-hot（`add_categorical_dummies`，默认关）** → 特征表 + 划分文件 | 一律 `shift(1)`，只看过去；时间排序统一走 `sort_by_time()`（无日期列时自动退化为按用户排） |
| `src/splits.py` | 按用户分组 / 按时间 / 随机划分 + 泄漏自检 | group 策略默认 |
| `src/train.py` | 多模型（未调参 + 调参）对比、验证集选优、train+val 重训、分位数模型 | **不读 test** |
| `src/evaluate.py` | 测试集指标、7 张图、切片误差、最差案例、报告生成 | **唯一使用 test 的地方** |
| `src/explain.py` | 全局置换重要性 + 局部反事实解释 + 中文文案 | 供界面与报告复用 |
| `src/predict.py` | 单条预测、预测区间、可信度标签（界面唯一入口） | 特征工程与训练期完全一致 |
| `app/app.py` | Streamlit 三步交互原型 | 不含任何模型逻辑；**提交表单与进结果页在同一轮脚本内完成**（不再"提交→`st.rerun()`→渲染"，见 `docs/04` 第 23 条）；输入值域由 `validate_inputs()` 兜底、步数上限由 `steps_upper_bound()` 从模型卡推导；预测异常一律显式 `st.error`，不允许"点了没反应"；凡是用到示例用户历史的地方一律写明"**示例用户**"；侧栏顶部有**「预测对象」切换**（`POPULATIONS` 是数据集说明书：控件种类/上下限/默认值 + `requires_feature` 对齐模型卡特征，含性别的那条线才渲染性别控件，见 `docs/03` §7.8.7） |
| `user_test/*` | 用户测试套件：任务脚本（`tasks.md`）、主试手册、可打印记录表、**实际使用的问卷原文（`questionnaire.md`）**、原始记录（`raw.csv`）与汇总（`summary.md`） | 未采集的字段写"未采集"，不补造；`raw.csv` 字段与记录表一一对应，新增列必须同步 `tasks.md` / `record_sheet.md` / `questionnaire.md` |
| `scripts/*` | 合成数据生成、端到端自检、界面自检；`gender_analysis.py` 出第二数据集（含性别变量）的描述统计/回归/消融报告 | 可独立运行 |

### 3.2 数据流（命令行一次跑通）

```
data/raw/... ──► data_io.clean ──► data/processed/*_clean.csv
                      │
                      ▼
        features.build_features（周期/滞后/滚动/个人基线）
                      │
                      ├──► data/processed/*_features.csv
                      └──► splits.make_splits ──► *_splits.json（train/val/test 索引）
                                     │
                                     ▼
              train.py：train 拟合 → val 选优 → train+val 重训
                                     │
                        models/model.pkl、quantiles.pkl、model_card.json
                                     │
                                     ▼
     evaluate.py（唯一使用 test）──► reports/metrics.md、error_analysis.md、figures/*.png
                                     │
                                     ▼
                  app/app.py：predict.py + explain.py → 三步交互
```

## 4. 关键设计决策（选择 / 备选 / 理由 / 代价）

| # | 决策 | 备选方案 | 选择理由 | 代价 / 限制 |
|---|---|---|---|---|
| 1 | 明确"预测时点 = 就寝前"，滞后/滚动特征一律 `shift(1)` | 不做时点定义，直接把所有列喂给模型 | 睡眠类数据最容易"用结果预测结果"，先定义时点才能界定合法输入 | 特征里不能用"卧床时间"等强相关变量，精度上限被压低，但这是诚实的上限 |
| 2 | 按 **user_id 分组**切分 | 随机切分 | 同一用户的多天记录高度相似，随机切分会让同一用户同时出现在训练与测试里，指标虚高 | 用户数少时 test 集用户数有限，指标波动更大（已用置信度标签与错误分析缓解） |
| 3 | `SimpleImputer` 放进 `Pipeline` | 先对全表 `fillna(median)` | 全表填补会把验证/测试集的分布信息泄漏进训练 | 每次预测要走一遍 Pipeline，速度略慢（可忽略） |
| 4 | 配置用 **Python 模块** | YAML / JSON / `.ini` | 目标机器没有 PyYAML；Python 配置可写注释、可类型检查、IDE 有补全 | 配置不再能被非 Python 工具读取（本项目无此需求） |
| 5 | 用 **分位数 GBDT（α=0.1/0.9）** 给预测区间 | 贝叶斯回归、MC Dropout、conformal prediction | 只需 scikit-learn，训练代价小；与非参数模型同族，行为易解释；验证集可直接测覆盖率 | 区间在两端可能偏窄；需要每次同时训练 3 个模型 |
| 6 | 解释用 **置换重要性 + 反事实归因** | SHAP / LIME | 无需额外依赖（本机没有 shap）；反事实文案（"如果就寝提前 1 小时…"）比 Shapley 值更贴近用户直觉 | 反事实归因是近似归因，相关特征会分摊影响，报告中必须写明不等于因果 |
| 7 | 可信度输出 **文字标签**（较高/中等/较低） | 直接给区间宽度数字 | 目标用户不具备区间宽度的解释能力，标签可直接指导决策 | 阈值是人为设定的（见 `src/metrics.py::confidence_level`），需要用户测试校准；**换用真实数据后已从"只看相对尺度"改为"相对 + 绝对双尺度"**，否则误差本身就大的模型会被判成"较高" |
| 8 | 界面用 **Streamlit** | Flask + 前端框架 / Jupyter | 纯 Python、几十行完成两步跳转与表单；课堂现场可即时演示 | 样式定制能力弱；不适合做正式产品 |
| 9 | 图表中文字体指定 **Microsoft YaHei** | 默认 DejaVu Sans | 否则中文标签全是方框，报告图不可读 | 跨平台时需换成系统中存在的字体（代码里已给多级回退） |
| 10 | 入口统一 `python -m 模块` + 控制台转 UTF-8 | 直接 `python src/train.py` | 避免相对导入失败；避免 Windows GBK 控制台导致中文/emoji 打印崩溃 | 多写一点样板代码（`setup_console()`） |

## 5. 代码规范与工程约定

1. **路径**：只允许在 `src/config.py` 里出现绝对/相对路径拼接，其它模块一律 `C.xxx_path()`；
2. **列名**：统一使用规范列名（`user_id` / `date` / `sleep_minutes` / `steps` …），
   与原始列名的映射全部写在 `config/dataset.py`；
3. **中文注释说明"为什么"**，函数首行 docstring 说明"输入 / 输出 / 约定"；
4. **可降级**：可选依赖必须 `try/except` 并有替代路径，不允许"装了才能跑"；
5. **友好报错**：模型缺失时 `src/predict.py` 抛出带修复命令的异常（`ModelNotTrainedError`），
   界面直接展示该命令；
6. **随机种子**：所有随机过程显式传 `random_state=C.random_seed()`；
7. **print 只用于进度**：所有结论性输出（指标、表格）都落盘到 `reports/`，不依赖控制台；
8. **不在界面里写模型逻辑**：界面只调用 `predict.py` / `explain.py`。

## 8. 已知技术债与后续扩展

| 技术债 / 限制 | 影响 | 后续方向 |
|---|---|---|
| 只有 30 名用户的公开数据 | 个体泛化能力有限 | 引入更大规模数据集；或做逐个用户的迁移学习 |
| 就寝时刻的原始分钟数在跨零点处不连续 | 模型主要依赖 sin/cos 周期编码与个人基线 | 把"就寝偏移量"（相对个人平均的环形差值）显式作为特征 |
| 反事实归因在强相关特征间会分摊影响 | 解释强度偏保守 | 装好 shap 后改用 TreeSHAP 做交叉验证 |
| 分位数区间的覆盖率只在验证/测试集上验证过 | 换人群可能失准 | 定期监控覆盖率；必要时用 conformal prediction 做校准 |
| 未做超时/缓存的模型热更新 | 重新训练需重启 Streamlit | 增加模型版本号与热加载 |
| 未做多用户并存与账号体系 | 只能演示单用户 | 接入真实数据源与身份体系（超出课程范围） |
| 第二数据集（`sleep_health_lifestyle`，374 人、含性别）**是横截面数据**：每人 1 条、无日期、字段近乎确定性相关 | 它的 MAE 3.56 分钟**不能**与线上真实设备的 41.9 分钟比较；性别效应只是数据集内部的统计关联，**不能**当因果或医学结论 | 若要把性别接入交互原型，需要另做一套"人群对照"页面（不能复用"载入最近 N 天 → 预测今晚"的口径）；或换一份**同时含性别与时间序列**的公开数据集（PMData / LifeSnaps 一类，尚未核实可用性） |
| ~~`app/app.py` 只服务线上 Fitbit 模型、**不暴露性别输入**~~ → **已于 2026-10-09 解决** | 侧栏「预测对象」现在可切换两条人群线：手环用户（Fitbit 日表）与睡眠健康人群（横截面、**含性别**） | 实现方式：`app/app.py` 里 `POPULATIONS` 是一份**数据说明书**——控件种类/上下限/默认值由说明书 + 模型卡渲染，字段用 `requires_feature` 对齐模型真实特征（不再出现"填了没反应"的假控件）；性别控件只在含该特征的模型上渲染，并写成 AppTest 回归断言（README 检查清单第 23 条、`docs/03` §7.8.7） |
| 用户测试是**远程自助问卷**（问卷星，4 人），缺 T2 / T3 / 焦虑措辞三类判定题 | 9 条通过线里 5 条**无法判定**，"能不能看懂不确定性""会不会当因果"这两个最关键的问题**没有证据** | 下一轮：把这 3 道题补进问卷，并**再招 3–5 人复测**（本轮 T1 用时也只能"自报"） |
| 样本只有 4 人（作业最低 3 人 ✅，目标 5 人未达到） | 通过线要按 4 人换算（`≥4/5` → 4 人全中），结论只能算方向性 | 尽量补到 5 人以上；汇总里已把分母写清楚，不用 `4/5` 冒充 |
| 参与者报告的"点生成预测没反应"**无法复现**（模型层与 AppTest 都正常） | 只能按最可能成因（表单提交后立刻 `st.rerun()` 的额外往返）加固，**不能声称"已修好"** | 界面上已把异常显式报错（不再静默）；后续可加前端错误上报或在真机录屏复现 |

## 9. 人工与 AI 的分工（摘要，详细见 `docs/04_ai_usage.md` 与 `docs/05_prompt_log.md`）

- **由人决定**：任务定义与预测时点、数据来源与合法性判断、验收标准、
  界面信息架构与文案口径、错误原因解释、用户测试与结论；
- **由 AI 辅助**：样板代码与文档草稿、API 用法查询、把决策翻译成代码与测试、
  发现并定位缺陷（如跨零点跳变、GBK 编码崩溃）；
- **人工验证**：所有 AI 产出都必须经过"能否跑通 + 结果是否合理 + 是否符合作业要求"三道检查，
  关键结论由人复核（见 04 文档的验证清单）。
